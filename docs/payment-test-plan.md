# 決済まわりのテスト手順

本番の Square に本物のカードで決済し、確認後に返金する前提の手順です。
**テストフェーズに入ったら、上から順に実施してください。**

いちばん避けたいのは「お客様が決済できない」状態です。この手順は、それが
起きる原因を影響範囲の大きい順に潰していく組み立てになっています。

---

## 0. 始める前に

- [ ] Vercel の環境変数 `SQUARE_ENVIRONMENT` が **`production`** になっている
      → `sandbox` のままだと決済が「成功」しても実際には課金されず、テストになりません
- [ ] Vercel の環境変数から **`SHOW_LOGIN_HINT` を削除**した
      → サイトは公開状態なので、残っていると管理画面のパスワードが誰でも見えます
- [ ] Vercel の Deployment Protection が **無効**（公開状態）
- [ ] **返金を誰がやるか決めた**
      入金先はお店の Square アカウントです。返金にはお店の Square ダッシュボードへの
      ログインが必要で、アクセストークンを持っていることとは別の話です
- [ ] クライアントに「テスト予約を数件入れます」と連絡した
      → 予約が入ると**店舗宛に通知メールが飛びます**。本物の予約と誤解されないように。
      連絡が難しければ、テスト中だけ `SHOP_NOTIFICATION_EMAIL` を外してください
- [ ] **一番安い商品**を使う（決済手数料は返金されないため。下記「費用」参照）

---

## テストケース

各ケースで **1件の予約を確定** させ、終わったら必ず後始末（末尾）をしてください。

### 1. iPhone / Safari — カード決済

- [ ] `https://gegege-event-reservation-app.vercel.app/` を開く
- [ ] 受取日 → 商品1個 → 確認画面
- [ ] カード入力欄が表示される
- [ ] カード番号を入力して「注文を確定する」
- [ ] **本人認証（3Dセキュア）の画面が出たか？** → 出た場合は完了させ、
      **下の「3Dセキュア」欄に記録**してください（出なくても異常ではありません）
- [ ] 完了画面が表示される
- [ ] 確認メールが届く
- [ ] 管理画面の「注文一覧」に出る／「製造計画」の数字が1増える

### 2. Android / Chrome — カード決済

- [ ] 上と同じ手順を Android で
- [ ] 特に**カード入力欄が表示されるか**を確認（ブラウザごとに事情が違うため）

### 3. iPhone — Apple Pay

- [ ] 確認画面に Apple Pay のボタンが出る
      → 出ない場合は、ドメイン登録が済んでいるか、Wallet にカードがあるかを確認
- [ ] ボタンから決済が完了する
- [ ] 管理画面に反映される

※ Apple Pay / Google Pay では 3Dセキュアの画面は出ません。端末側で本人確認が
済んでいるためで、正常な動作です。

### 4. Android — Google Pay

- [ ] 確認画面に Google Pay のボタンが出る
- [ ] ボタンから決済が完了する
- [ ] 管理画面に反映される

## 3Dセキュア（記録欄）

3Dセキュアは**毎回必ず実行されます**が、認証画面が出るかどうかはカード会社が
決めます。リスクが低いと判断されれば画面は出ません（フリクションレス、一般に
8割程度）。画面が出ないのは異常ではありません。

- 1〜2 のテストで**認証画面が出た** → チャレンジ経路も検証済み。ここは完了です
- **一度も出なかった** → 認証画面が出るパターンだけ未検証。下記のどちらかを選ぶ

**選択肢A：サンドボックスで確認する（推奨・無料・30分程度）**
Square のサンドボックスには強制的に認証画面を出すテストカードがあります。
環境変数をサンドボックスの認証情報に差し替えて確認し、本番に戻すだけです。
お金は動きません。

**選択肢B：許容する**
認証が完了しなかった場合、お客様には「カード会社の本人認証が完了しませんでした。
もう一度お試しください。」と表示され、**注文は作られず在庫も減りません**。
画面はそのままなので別のカードで再試行できます。二重課金や予約の取りこぼしは
起きない作りです。

記録：

| 回 | 端末 | 認証画面 | 結果 |
| --- | --- | --- | --- |
| 1 | iPhone Safari | 出た / 出ない | |
| 2 | Android Chrome | 出た / 出ない | |

## 後始末（テストごとに必ず）

**順番が大事です。Square で返金しても、アプリ側の在庫は戻りません。**

1. [ ] 管理画面 →「注文一覧」→ 該当の注文を**キャンセル**
       - ダイアログに**決済ID**が出るので控える
       - キャンセルすると受付枠が戻ります。**キャンセルは取り消せません**
2. [ ] Square ダッシュボードで、その決済IDを検索して**全額返金**
3. [ ] 管理画面の「製造計画」で、数字が元に戻っていることを確認

キャンセルを忘れると、受付枠が減ったままになり、**当日お店が余分に作ります**。

---

## 費用について

- 返金処理自体は無料ですが、**元の決済手数料（約3.25%）は戻らず店舗負担**です
- 1,000円の商品なら1回あたり約32円。4ケースで130円程度
- カード明細に返金が反映されるまで **2〜7営業日**かかります。すぐ戻らなくても異常ではありません

---

## 検証できないこと

このテストで確認できるのは「テストした時点で壊れていないこと」だけです。
イベント期間中に Square 側の変更などで壊れた場合、**お客様は黙って離脱するため
こちらでは気づけません**。

決済が失敗したときに管理者へ通知メールを飛ばす仕組みを追加できます。
期間中の保険として検討してください（未実装）。
